Utextility revamp proposal

Prepared for Pranshu Choubey · Product and engineering review · 19 November 2026

Build for the person who copies text out of one application and has to repair it before using it in another. Give them a named cleanup routine, keep the original in view, and let them inspect exactly what changed.

Who would open this twice

A developer preparing weekly release notes may copy paragraphs from a PDF, paste a list from a ticket, then trim the final copy to fit a publishing limit. Today that work can mean deleting hard returns by hand, searching for duplicate lines and opening a counter. A saved sequence earns a bookmark if the same person can use it again next week and trust the output.

Your March 2025 portfolio entry emphasizes case conversion, whitespace cleanup, live counts and phone access. The newer case study describes three occasions when you needed the tool. You had stray spaces to clean, a heading to fix or a word limit to meet. A pilot can establish how often other people encounter those jobs. Earlier project catalogue · Current case study

Where the tool can earn its place

Text Mechanic already removes duplicate lines locally and keeps the first occurrence. CyberChef already chains operations into browser-side recipes. For someone publishing release notes, the decision that costs attention is whether the cleanup preserved their meaning. Utextility can put the original beside the proof and show what happened to every space or line break in a short paste. Text Mechanic duplicate handling · CyberChef workflow

Working release. The separate v2 implements three starting recipes, 23 individual operations, a change view, word and character budgets, saved recipes and plain-text import and export. The recommended visual direction is a letterpress proof room.

What would justify a wider release

Watch someone clean a real, shareable paste by their usual method, then with Utextility. Check whether the result preserves the paragraph or list structure they intended. A faster copy that silently merges a heading with body copy is a failed attempt. A repeat visit with a second document is stronger evidence than a positive first impression.

Working release

Three reasons to open the desk

Clean a paste before sending it

A writer copies a paragraph from a narrow PDF column. Its hard returns survive the paste, and its words contain stray spacing. “Clean a paste” trims each line, collapses horizontal spacing and joins adjacent prose lines. Empty lines and common list-marker lines keep their boundaries. A poem or an unmarked heading can still resemble wrapped prose. The writer can inspect Changes and remove the joining step.

Tidy a list without losing its order

A support lead combines two lists of labels. “Tidy a list” trims edges, drops blank rows and removes later exact duplicates. The first occurrence wins, so the original ordering survives. For a case-insensitive list the user can add lowercase before deduplication and inspect the result. That also lowercases the labels, a visible tradeoff to discuss with pilot users.

Make a batch of readable slugs

A developer pastes headings, one per line. “Make slugs” separates case boundaries, keeps letters from multiple scripts, applies kebab case and drops empty output lines. The result is a set of path segments. Choosing unique site routes and percent-encoding them belongs at the publishing boundary. For code, the same tool index offers snake, camel and Pascal case.

Carry a successful result into the next task

Each recipe starts with a labeled example. A user’s own text survives recipe switches. They can inspect additions and deletions, set a word or character limit, copy the proof or download UTF-8 text. If the destination permits 250 words and the proof has 253, the desk reports three words over the limit. Named recipes retain ordered steps for the next session. “Use alone” keeps a one-off operation one choice away in the tool index.

The editor imports UTF-8 plain text, including text-based Markdown and CSV files. CSV is treated as lines of text. To clean a PDF excerpt, copy its text into the editor.

Weaving draft

Concept. Indigo, madder and flax set the palette. Spectral labels the rows and Work Sans labels the controls. Source lines form rows and operations form columns. Selecting a marked crossing reveals which step changed that line and shows its before and after text.

Implementation

How the new version works

The new folder is a static application with locally bundled fonts and plain JavaScript. It opens from disk and can also run on any static web server. The old React setup has little reusable infrastructure around its algorithms. Extracting the number-spelling rules and preserving the original tool coverage makes a small implementation practical. React has also retired Create React App for new projects. React’s Create React App announcement

BoundaryImplementation and extension contract
Operation catalogue
engine.js		Each entry has a stable ID, human label, group, description and text-to-text function. A recipe is an ordered list of IDs. Adding a tool requires a behavior example, including what it does to line boundaries. The catalogue drives both execution and help.
Evaluation
engine.js, worker.js		Normalize CRLF and CR to LF at the input boundary. Derive the proof from the source on each run. A failing step reports its position and disables export. Over HTTP, inputs of 4,000 or more UTF-16 units use a worker when available. A version check discards stale results.
Composition and state
workbench.js		Keep the draft, derived proof, limit and one-step source replacement history in tab memory. Local storage holds named recipe definitions and appearance. A denied storage write leaves the current recipe usable. Source edits during a file read take priority over its late result.
Interface and export
index.html, styles.css		Native input and dialog elements support keyboard use. The UI renders user text through text nodes. It waits for the clipboard write to succeed and selects the proof for manual copying if the browser denies access. A local Blob provides UTF-8 downloads.

Limits people can reason about

The current ceiling is 100,000 UTF-16 units per input and 16 steps per recipe. The character budget counts visible grapheme clusters when supported, so an emoji can be one character yet use several input units. Word and sentence boundaries use the browser locale. Title case and sorting follow English conventions. Reading time assumes 200 words per minute. Browser text segmentation

The change view compares word, spacing and punctuation tokens. It switches to a full-text comparison suggestion above 32,000 combined units or a 250,000-cell comparison table. The full source and proof stay available. Direct-file use computes on the main thread. These limits bound work and should be revisited with samples from the pilot.

How to use frontier models here

Start during development. Give a model synthetic examples of mixed scripts, whitespace, list markers and emoji, then have a human decide the expected output. For a later step picker, send a user-authored instruction on explicit invocation and validate the proposed IDs locally. The ordinary transform path can continue to work offline. A pilot diary can record the task and outcome without retaining anyone’s pasted text.

Verification and remaining evidence

The 32 regression tests cover all 23 tools, full recipes, ordering, counts, Unicode fallback, comparison reconstruction and limits. Chromium checks exercised direct-file and HTTP entry, import and download bytes, recipe save/delete/restore, clipboard success and denial through a test double, a large worker job and responsive widths from 320 to 1,440 pixels. The tested flows made zero third-party requests.

Before a public launch, test on a physical Android phone and in Safari, observe keyboard and screen reader users completing a paste, and measure typing latency on a midrange device. The pilot determines whether people return. Keep the existing portfolio link serving its current release until a separately deployed v2 passes those checks.
